# Ctrl + Dark code, security, and UI/UX audit

Reviewed commit `6994e74` on November 27, 2026. The highest priorities are authenticating the local daemon, surfacing Windows lock failures, and protecting the saved display layout when the daemon is busy or the computer is undocked.

## High priority

| # | Finding and impact | Recommended fix |
|---|---|---|
| 1 | **The launcher trusts the identity and URL returned by a machine-wide named pipe.** The daemon mutex is session-local, but the pipe has one fixed name across sessions. The listener uses default security and the client accepts a reply without checking the server's user or session. The browser path passes the returned string directly to the Windows shell. An unexpected local endpoint can therefore direct what the launcher opens. The client also leaves the default pipe impersonation level in effect. This is a local trust issue whose consequences depend on the accounts and privileges involved. [Pipe server](../src/ipc.rs#L124) · [Client](../src/ipc.rs#L348) · [Shell launch](../src/autostart.rs#L51) · [WebView navigation](../src/bin/ui.rs#L157) | Scope the pipe name and ACL to the logon session, protect initial ownership, validate the connected server identity, and request only the impersonation level needed. Parse and allowlist the expected loopback HTTP URL before either launch path or subsequent navigation. |
| 2 | **A failed workstation lock can leave an unattended session unlocked behind dark monitors.** With lock-on-sleep enabled, the controller selects ordinary input wake. If Windows rejects the lock, the full-sleep worker writes a warning, powers down the displays, and returns its ordinary success result. The selective path also reports success after logging a lock failure. The user receives no indication that the security-sensitive part failed. [Wake-mode selection](../src/controller.rs#L484) · [Selective lock](../src/controller.rs#L1806) · [Full sleep](../src/controller.rs#L1823) | Surface a distinct lock failure in the tray and panel. For full sleep, stop before blanking when Windows rejects the lock. For a selective layout already applied, report both outcomes and keep a visible recovery path. Use the session-lock notification when confirmation is required. |
| 3 | **An IPC timeout can start a second recovery or overwrite the rollback snapshot.** The CLI falls back to standalone display operations on any request error, including a timeout after the daemon received the request. A busy daemon can consequently race another topology writer. A standalone snapshot can also bypass the daemon's phase check and replace the healthy baseline with the current partial desktop. The benchmark uses a short status request as its exclusion check as well. [Recovery fallback](../src/bin/cli.rs#L232) · [Snapshot fallback](../src/bin/cli.rs#L308) · [Benchmark](../src/bin/cli.rs#L484) · [Daemon snapshot guard](../src/controller.rs#L1002) | Distinguish a missing endpoint from a request with an unknown outcome. Serialize hardware changes and baseline replacement across processes. Return an actionable error on ambiguous delivery and reserve explicit standalone operation for cases where it can obtain ownership. |
| 4 | **Sleeping an undocked laptop can overwrite its saved dock layout.** Startup and display-change handlers keep a larger previous snapshot. The automatic capture immediately before sleep checks only whether currently available monitors are active. On an undocked laptop that check passes, and a one-screen capture replaces the three-screen baseline on disk and in memory. Restore then lacks the saved positions when the dock returns. The same call also discards capture errors and proceeds with the display change. [Pre-action capture](../src/controller.rs#L469) · [Snapshot replacement](../src/controller.rs#L1012) · [Display-change retention](../src/controller.rs#L892) | Separate the immediate rollback for the current operation from the durable dock layout. Preserve missing displays or keep per-topology baselines, and surface capture failures before a change that needs rollback. |
| 5 | **A delayed selective-operation result can overwrite a newer sleep state.** For example, a selective change is queued, then the user requests full hotkey-only sleep. If the earlier selective job fails, its completion handler changes the phase to Active or Selective Off. The later sleep completion only logs success. The input guard can remain armed while the controller reports Active, so the normal toggle can initiate another sleep operation. [Sleep transition](../src/controller.rs#L488) · [Failure and sleep completion](../src/controller.rs#L645) | Associate each job and completion with its originating operation. Apply state and guard changes only to the current operation, or serialize incompatible requests through completion. Test both completion orders with an injected failure. |

Windows documents the default pipe ACL and impersonation behavior. The pipe's remote-client rejection and the HTTP server's loopback binding are valuable controls for a different boundary. [Microsoft named-pipe access rights](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights) · [Microsoft named-pipe impersonation](https://learn.microsoft.com/en-us/windows/win32/ipc/impersonating-a-named-pipe-client)

## Additional security and correctness findings

| # | Priority | Finding and impact | Recommended fix |
|---|---|---|---|
| 6 | Medium | **The default browser can send the daemon's API credential to another loopback service.** The page sets the same bearer value used by the API in a host-wide cookie for `127.0.0.1`. When the same browser profile visits another qualifying service on that host, the browser can include the cookie regardless of port. That service can receive a credential valid for the daemon session. The initial URL also retains the token. [Cookie and API checks](../src/web_server.rs#L343) · [Launch URL](../src/web_server.rs#L127) · [RFC 6265 §8.5](https://www.rfc-editor.org/rfc/rfc6265#section-8.5) | Exchange a one-use launch credential for an origin-scoped session, remove it from the visible URL, and keep the reusable API credential out of host cookies. |
| 7 | Medium | **The factory profile can put every display to sleep on unrelated hardware.** A fresh install registers Ctrl+Alt+D for two specific monitor models. If neither is attached, the keep list matches nothing, every available display becomes an off target, and the planner selects full sleep. The default wake mode then suppresses ordinary input. The same case arises after unplugging the only monitor named in a user's keep list. [Factory profile](../src/config.rs#L199) · [Planner](../src/controller.rs#L1486) | Leave the example unbound until configured. Treat a keep list with zero connected matches as unavailable and explain which targets are missing. Keep explicit all-display sleep available. |
| 8 | Medium | **Switching profiles can wake a monitor explicitly excluded by the new profile.** With A on and B/C off, toggle a profile that keeps A+B and excludes C. The layout is unsatisfied because B is off, but the only off target, C, is already off. The controller takes its “no active target” branch and calls Wake All, bringing C back too. [Toggle decision](../src/controller.rs#L412) · [Keep-layout planner](../src/controller.rs#L1500) | Distinguish an already-satisfied layout from an unsatisfied keep list that needs activation. Route the latter directly to the keep-layout planner. |
| 9 | Medium | **Applying a partially matched keep list can silently disable a requested screen.** When switching layouts, any nonempty filtered snapshot is accepted. A newly attached display requested alongside a saved display may be absent from that snapshot. The worker verifies only the keys in its reduced plan, so the operation can report success with the new display missing. [Filtering decision](../src/controller.rs#L538) · [Worker verification](../src/controller.rs#L1914) | Require coverage of every connected requested display before applying, carry the original expected set into verification, and preserve the current topology if a complete plan cannot be built. |
| 10 | Medium | **Quitting during hard recovery can interrupt the rollback.** A hard bounce temporarily removes active paths, waits 450 ms, then restores them. The controller discards the worker join handle and posts quit immediately on shutdown. The process can exit with the paths still disabled. [Worker lifetime](../src/controller.rs#L204) · [Bounce and restore](../src/display/recovery.rs#L465) · [Shutdown](../src/controller.rs#L1302) | Stop accepting work on exit and wait for the worker to finish or roll back the active topology change before terminating. |
| 11 | Medium | **Restoring ordinary windows can move them off-screen after an origin change.** The restore code identifies the surviving monitor and computes its current work area. For a non-maximized window it passes the old absolute coordinates to Windows. If the previous primary is unplugged and the surviving monitor moves to the origin, those coordinates can fall outside the desktop. The reported restore count also includes every queued window even if positioning fails. [Placement](../src/window_restore.rs#L290) · [Work area and count](../src/window_restore.rs#L375) | Translate the saved offset relative to the old work area into the new one, clamp a usable portion of the window on-screen, and report positioning failures separately. |
| 12 | Medium | **A timed-out settings save can still take effect later.** HTTP gives up after three seconds, but its queued apply operation has no expiry. Once the window thread resumes it can persist the settings after the user has seen a failure. [HTTP deadline](../src/web_server.rs#L881) · [Deferred apply](../src/controller.rs#L1178) | Put a deadline on queued writes before they start. For writes already in progress, expose a result the panel can reconcile before offering a retry. |
| 13 | Medium | **An unrelated settings save can undo an autostart change from the tray or CLI.** The panel always posts its checkbox value, while the optimistic concurrency check covers the TOML configuration only. In Edge, a shortcut draft opened with autostart off wrote it back to off after the fixture switched it on. [Save payload](../src/ui/app.js#L1429) · [Daemon comparison and application](../src/controller.rs#L1174) | Send autostart only when the user edits it and compare its original value before updating the registry. Apply the same conflict feedback used for configuration edits. |
| 14 | Medium | **CLI commands require a healthy HTTP panel even when pipe IPC is working.** The daemon continues serving the pipe after HTTP initialization fails. The common CLI startup helper waits for a nonempty panel URL, so commands such as On can time out before sending their pipe request. [Daemon startup](../src/bin/daemon.rs#L111) · [Launcher readiness](../src/launcher.rs#L150) · [CLI helper](../src/bin/cli.rs#L629) | Use successful IPC status for CLI readiness. Wait for the panel URL only when opening the panel. |

## Control Panel and accessibility findings

| # | Priority | User-visible behavior | Recommended fix |
|---|---|---|---|
| 15 | Medium | **Renaming a profile changes which monitors it will match.** In Edge, saving only a new label changed the include selector from the friendly name `Desk Display` to the connector-specific key `display#external#2`. A profile that used to match a replacement or reconnected display can stop matching it. Model and GDI selectors follow the same conversion path. [Editor initialization](../src/ui/app.js#L970) · [Save selection](../src/ui/app.js#L1042) | Preserve the original selectors on untouched rows. Convert a selection to a specific device key only when the user changes that selection. |
| 16 | Medium | **“Test Layout Now” can leave a real layout change or lock in effect after Cancel.** The button sends a normal toggle or off operation, including the configured workstation-lock behavior. Its result can differ from the displayed preview when the layout is already active. Cancel simply closes the dialog, and there is no timed rollback. [Test button](../src/ui/app.js#L1178) · [Server dispatch](../src/web_server.rs#L952) · [Cancel](../src/ui/app.js#L1199) | Make testing apply the displayed layout deterministically, suppress lock automation for previews, and offer a timed revert with explicit confirmation to keep it. |
| 17 | Medium | **Recovery and operation errors can disappear before a user can act.** In Edge a hotkey warning hid a simultaneous recovery error. Dismissing the warning still left the recovery error hidden. A separate shortcut-install error disappeared on the next successful background poll, although the operation had failed. [Polling and alert priority](../src/ui/app.js#L328) · [Action errors](../src/ui/app.js#L756) | Track errors individually. Keep an action failure visible until dismissed or resolved, and give a recovery failure precedence over shortcut warnings. |
| 18 | Medium | **The failed and recovering screens offer misleading actions.** In the failed phase the prominent control says “Sleep All,” but the toggle handler starts recovery. In the recovering phase Edge kept Wake All enabled even though the server rejects that request. [Header label](../src/ui/app.js#L399) · [Control enablement](../src/ui/app.js#L52) · [Toggle handler](../src/controller.rs#L397) · [API rejection](../src/web_server.rs#L1036) | Show “Retry recovery” in the failed phase. Disable incompatible display actions while recovering, and use explicit sleep and wake commands so a poll-to-click state change cannot reverse intent. |
| 19 | Medium | **Mirrored displays cover one another on the interactive map.** In Edge, two equal-resolution displays at the same coordinates produced two buttons at the same position. Hit-testing the center of either returned the second display. Separate monitor cards remain usable. [Map geometry and click target](../src/ui/app.js#L456) | Render a single mirrored group with a member chooser, or provide independently reachable member controls beside the shared rectangle. Test pointer hit targets as well as bounding boxes. |
| 20 | Low | **The appearance preference can reset after a daemon restart.** The panel stores it in origin-scoped local storage, while the daemon normally gets a new port on restart. Both browser and WebView visits to the new origin can fall back to System. [Theme persistence](../src/ui/app.js#L105) · [Port allocation](../src/web_server.rs#L120) | Persist appearance in application preferences and include it in the initial panel state. Keep the immediate preview when the user selects a theme. |

The existing tests protect keyboard focus during polling and exercise a range of screen sizes. The panel also provides monitor cards alongside the map, which gives users a working alternative in a mirrored layout. The most valuable follow-up tests are a controlled daemon/CLI timeout, a failed Windows lock, an undock–sleep–redock cycle, and a worker completion arriving after a newer command. Each covers a user-visible failure that the passing suites currently miss.
